
# W-1-1
## front
Vyjmenuj základní architektury na straně serveru používané při návrhu webových aplikací.
## back
- Monolitická architektura
- Microservices (mikroslužby)
- Serverless architektura

# W-1-2
## front
K čemu slouží architektura microservices, a jaký je její základní princip?
## back
- Rozdělení aplikace na malé, nezávisle nasaditelné služby (mikroslužby).
- Každá služba řeší konkrétní doménovou oblast.
- Snadnější škálování, správa a údržba jednotlivých částí.
- Komunikace mezi službami typicky přes síť (REST API, messaging).

# W-1-3
## front
Popiš princip serverless architektury.
## back
- Kód běží ve formě tzv. funkcí (lambdas) v cloudovém prostředí.
- Maximální zjednodušení infrastruktury, správa serverů je zcela na poskytovateli služby (cloud).
- Platí se podle využitých zdrojů (tzv. pay-per-use model).
- Vysoká škálovatelnost.

# W-1-4
## front
Co je REST (Representational State Transfer) a jaké jsou jeho základní principy?
## back
- Architektonický styl pro návrh webových API.
- Základní principy:
  - klient-server
  - stateless (bezuživatelský stav mezi požadavky)
  - cacheable (možnost cachování odpovědí)
  - jednotné rozhraní založené na zdrojích (uniform interface - resources)
  - layered system (vrstvený systém, klient nevidí za load balancer/proxy)

# W-1-5
## front
Vysvětli princip REST vlastnosti "stateless".
## back
- Server neudržuje žádný stav o klientech mezi jednotlivými požadavky.
- Každý požadavek od klienta musí obsahovat veškeré informace potřebné ke zpracování.

# W-1-6
## front
REST: Co znamená požadavek "cacheable"?
## back
- Odpovědi na REST požadavky mohou být ukládány do cache (mezipaměti).
- Zvyšuje výkon a snižuje zátěž serveru.
- Server určuje, které odpovědi lze cachovat (např. pomocí HTTP hlaviček).

# W-1-7
## front
Co znamená uniform interface v REST architektuře?
## back
- Jednotné rozhraní je založené na práci se zdroji (resources).
- Definovaná sada operací (např. HTTP metody GET, POST, PUT, DELETE).
- Všechny operace jsou dostupné stejným způsobem bez ohledu na typ zdroje.

# W-1-8
## front
REST: Co znamená "layered system"?
## back
- Architektura je rozdělena do vrstev (např. load balancer, proxy, server).
- Klient nepozná, jestli komunikuje přímo se serverem nebo přes prostředníka.
- Dává možnost rozšiřitelnosti, bezpečnosti a škálování.

# W-1-9
## front
Jak se v REST přistupuje ke konkrétnímu zdroji? Uveď příklad URI.
## back
- Ke zdroji se přistupuje pomocí URI (Uniform Resource Identifier).
- Např. $/books/[id]/authors$

# W-1-10
## front
Co znamená, že operace v REST API je idempotentní? Uveď příklad.
## back
- Vícenásobné volání téže operace má na zdroji vždy stejný efekt, jako kdyby byla volána jednou.
- Příklad: $PUT /counter$ s hodnotou 10 (nastaví vždy na 10, bez ohledu na počet volání).

# W-1-11
## front
Vysvětli REST vlastnost "safe" na příkladu.
## back
- "Safe" znamená, že operace nemění stav zdroje a lze ji cacheovat.
- Příklad: $GET /books$ pouze vrací seznam knih, nemění data na serveru.

# W-1-12
## front
Uveď jednotlivé HTTP metody používané v REST a jejich vlastnosti (idempotence, safe).
## back
- $GET$ — idempotentní, safe
- $PUT$ — idempotentní, není safe
- $DELETE$ — idempotentní, není safe
- $POST$ — není safe, není idempotentní
- $PATCH$ — není safe, není idempotentní

# W-1-13
## front
Které HTTP metody RESTu jsou idempotentní?
## back
- $GET$
- $PUT$
- $DELETE$

# W-1-14
## front
Které HTTP metody RESTu jsou "safe"?
## back
- $GET$

# W-1-15
## front
Jaké návrhové vzory souvisí s webovou aplikací na serverové straně?
## back
- Monolitická architektura
- Microservices (mikroslužby)
- Serverless (funkce jako služba)

# W-1-16
## front
Vyjmenuj základní vlastnosti REST architektury.
## back
- Klient-server
- Stateless (bezustavový)
- Cacheovatelnost
- Jednotné rozhraní (uniform interface)
- Vrstvený systém (layered system)

# W-1-17
## front
U které REST metody je typickým příkladem požadavek, který NENÍ ani safe, ani idempotentní?
## back
- $POST$ (například vytvoření nového objektu)
- $PATCH$ (částečná úprava dat)

# W-1-18
## front
Co představuje resource v REST architektuře?
## back
- Entitu nebo objekt v systému, který lze jednoznačně identifikovat pomocí URI.
- Např. kniha, autor, objednávka apod.

# W-1-19
## front
Vysvětli rozdíl mezi $PUT$ a $POST$ v REST architektuře.
## back
- $PUT$: slouží k nahrazení nebo vytvoření konkrétního zdroje, je idempotentní.
- $POST$: slouží k vytvoření nového zdroje nebo odeslání dat ke zpracování, není idempotentní.

# W-1-20
## front
Proč je idempotence důležitá v REST API?
## back
- Zaručuje, že opakovanými identickými požadavky nedojde ke změně stavu nad rámec prvního požadavku.
- Usnadňuje zotavení z chyb a zajišťuje předvídatelné chování API.
