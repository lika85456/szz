
# W-1-1
## front
Jaký je základní rozdíl mezi SPA (Single Page Application) a MPA (Multi Page Application)?
## back
- SPA (Single Page Application):
  - Načítá jedinou HTML stránku, dynamicky mění její obsah prostřednictvím JavaScriptu bez úplného reloadu stránky.
  - Interakce (např. přechody mezi sekcemi) nezpůsobují načtení nové stránky ze serveru.
- MPA (Multi Page Application):
  - Každá interakce/sekce má vlastní URL a načítá novou HTML stránku z backendu.
  - Přepínání stránek znamená kompletní reload stránky a často ztrátu stavu aplikace na straně klienta.

# W-1-2
## front
Uveďte hlavní výhody a nevýhody SPA oproti MPA.
## back
Výhody SPA:
- Rychlejší a plynulejší uživatelské rozhraní (méně reloadů, přechody animovatelné)
- Možnost využít client-side routing, lepší uživatelský zážitek v offline režimu

Nevýhody SPA:
- První načtení bývá pomalejší (větší JavaScript bundle)
- SEO je složitější (obsah generovaný na klientovi)
- Vyšší složitost aplikace (správa stavu, routing na klientovi)

# W-1-3
## front
Co je to PWA (Progressive Web App) a jaké má klíčové vlastnosti?
## back
- PWA je webová aplikace, která poskytuje uživatelský zážitek blízký nativním mobilním aplikacím.
- Klíčové vlastnosti:
  - Responsivní design (funguje na každém zařízení)
  - Offline funkčnost díky service workerům
  - Možnost instalace na domovskou obrazovku (Add to Home Screen)
  - Push notifikace
  - Bezpečnost (vyžaduje HTTPS)

## front
Vyjmenujte a stručně popište klíčové technologie a standardy používané na straně klienta webové aplikace (prohlížeč, uživatelský agent).

# W-1-5
## front
K čemu slouží AJAX v prohlížeči?
## back
- Asynchronní komunikace s webovým serverem, aniž by došlo k úplnému reloadu stránky.
- Umožňuje dynamicky aktualizovat obsah stránky na základě dat ze serveru (například načítat nové položky seznamu).
- Základní implementace AJAXu využívá objekt XMLHttpRequest nebo novější Fetch API.

# W-1-6
## front
Jaké jsou výhody a nevýhody použití AJAXu (asynchronních požadavků) ve webové aplikaci?
## back
Výhody:
- Rychlejší uživatelská odezva (není nutné refreshovat stránku)
- Plynulé načítání dat
- Možnost částečných aktualizací stránky

Nevýhody:
- Složitější kód (nutnost spravovat stav UI při asynchronních operacích)
- Potenciální bezpečnostní a synchronizační problémy (race conditions)
- Obtížněji laditelný kód

# W-1-7
## front
Čím se liší XMLHttpRequest a Fetch API při práci s AJAX požadavky v prohlížeči?
## back
XMLHttpRequest:
- Původní API pro asynchronní požadavky v JavaScriptu
- Má složitější a méně přehledné rozhraní pro práci s promise/async
- Omezené možnosti pro čtení streamovaných dat

Fetch API:
- Novější a snadnější na použití, využívá Promise
- Lepší podpora pro request/response streaming
- Čitelnější syntaxe a lepší možnost práce s různými response typy (JSON, Blob apod.)

# W-1-8
## front
Jaké jsou hlavní výhody použití Fetch API oproti XMLHttpRequest?
## back
- Moderní Promise-based API (lepší práce s asynchr. kódem)
- Jednodušší a čitelnější syntaxe
- Lepší možnosti pro cancelování požadavků pomocí AbortController
- Snazší práce s různými formáty dat (JSON, Blob, FormData atd.)

Vyjmenujte alespoň tři důležité Browser APIs, které jsou dostupné vývojářům ve webových prohlížečích.

# W-1-10
## front
K čemu slouží react-query knihovna při vývoji SPA?
## back
- Umožňuje spravovat stav dat načítaných ze serveru jednoduše a efektivně (cacheování, synchronizace, polling, automatická aktualizace)
- Řeší obtíže s načítáním a obnovou dat z API v React aplikacích (např. řešení fetching, caching, synchronizace různých datových požadavků)
- Pomáhá s optimalizací výkonu díky chytrému uložení dat do cache

# W-1-11
## front
Jaká jsou hlavní omezení AJAXu z hlediska zabezpečení a interoperabilty?
## back
- Stejná-originální politika (same-origin policy): AJAX požadavky z webové stránky mohou komunikovat pouze se stejnou doménou, pokud server neumožní CORS (Cross-Origin Resource Sharing)
- CORS: Povolení/potlačení cross-origin požadavků
- Potenciální XSS/CSRF zranitelnosti, pokud není správně implementováno ověřování a validace vstupů

# W-1-12
## front
Napište alespoň tři rozdíly mezi MPA, SPA a PWA.
## back
- MPA: Každý pohled načítá novou HTML stránku; tradiční architektura, vyšší kompatibilita se SEO
- SPA: Jedna stránka a dynamické změny obsahu přes JavaScript; rychlejší interakce, těžší SEO
- PWA: Moderní aplikace s možností offline použití, instalací a push notifikací, nezáleží jestli je SPA nebo MPA – je to soubor vlastností/progressive enhancement

# W-1-13
## front
Vysvětlete, co znamená asynchronní zpracování požadavků ve webovém prohlížeči a proč je to důležité.
## back
- Asynchronní zpracování znamená, že webová aplikace může odeslat požadavek na server a pokračovat v běhu (UI zůstává reagující) bez čekání na odpověď serveru.
- Umožňuje načítat data, aktualizovat UI nebo odesílat formuláře bez reloadu stránky.
- Je důležité pro rychlou a plynulou uživatelskou zkušenost (zabraňuje "zamrznutí" stránky během komunikace se serverem).

# W-1-15
## front
Jaký je rozdíl mezi Browser API a Web API?
## back
- Browser API: Rozhraní poskytovaná webovým prohlížečem pro interakci se specifickými funkcemi zařízení/systému (např. DOM API, Storage API, Geolocation).
- Web API: Může označovat jakékoliv rozhraní dostupné pro webové technologie (včetně serverových služeb poskytujících data), ale často se používá jako synonymum pro rozhraní pro komunikaci mezi aplikací a serverem (REST API apod.).

# W-1-16
## front
Jak napíšete jednoduchý asynchronní požadavek pomocí Fetch API pro načtení JSON dat ze serveru?
## back
```javascript
fetch('https://example.com/api/data')
  .then(response => response.json())
  .then(data => console.log(data));
```
- Používá Promise, je čitelnější než XMLHttpRequest.

# W-1-17
## front
Proč je nutné řešit cacheování a synchronizaci dat při asynchronní komunikaci ve SPA aplikaci?
## back
- Kvůli optimalizaci výkonu (nechceme opakovaně stahovat stejná data)
- Zabraňujeme nekonzistenci dat mezi stavem na serveru a stavem na klientovi
- Reagujeme pohotověji na uživatelské akce (ukládáme si už jednou načtená data do cache, případně je v backgroundu aktualizujeme)

# W-1-18
## front
Jak souvisí service workery s technologiemi PWA?
## back
- Service worker je speciální skript, který běží na pozadí prohlížeče a umožňuje PWA:
  - Zachytávat a manipulovat síťovými požadavky (offline režim, cacheování)
  - Zpracovávat push notifikace
  - Provádět periodické aktualizace obsahu (background sync)

# W-1-19
## front
Jaký je účel Browser Storage API a jaký je rozdíl mezi LocalStorage, SessionStorage a IndexedDB?
## back
- Browser Storage API slouží k ukládání dat na straně klienta.
  - LocalStorage: perzistentní data, která přežívají i zavření prohlížeče (key-value)
  - SessionStorage: data pouze po dobu otevření záložky/okna (key-value)
  - IndexedDB: databázová struktura, vhodná pro větší množství dat a komplexní struktury

# W-1-20
## front
Které vlastnosti musí splňovat aplikace, aby byla považována za PWA?
