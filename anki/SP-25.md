
# SP-25-1
## front
Co je úkolem transportní vrstvy v síťové komunikaci?
## back
- Zajišťuje doručení dat konkrétním aplikacím (přidává k IP adrese ještě port).
- Řeší spolehlivost dodání dat pomocí různých mechanismů, např. stop and wait, stop and go, sliding window.

# SP-25-2
## front
Vyjmenuj tři způsoby zajištění spolehlivosti doručení dat na transportní vrstvě.
## back
- Stop and wait (jednoduchý mechanismus, doručuje data v pořadí, ale neefektivní)
- Stop and go (přijímač posílá vysílači signály stop a go, nezajišťuje doručení)
- Sliding window (klouzavé okénko, odesílají se všechny pakety v okénku, čeká se na ACK posledního)

# SP-25-3
## front
Jaké vlastnosti má protokol TCP?
## back
- Zajišťuje spolehlivé doručení dat.
- Garantuje doručení i pořadí paketů.
- Je duplexní (obě strany jsou vysílač i přijímač).
- Používá handshake pro navázání a ukončení spojení.
- Řízení toku dat mechanismem "sliding window" (klouzavé okénko).
- Řeší zahlcení (congestion control) pomocí CWL (congestion window length).

# SP-25-4
## front
Jak probíhá navazování TCP spojení? (Název mechanismu + obrázek)
## back
- Pomocí třícestného handshake (three-way handshake).
- Postup:
  1. Klient odešle SYN segment.
  2. Server odpoví SYN-ACK.
  3. Klient odešle ACK.

# SP-25-6
## front
Co je klouzavé okénko (sliding window) u TCP a k čemu slouží?
## back
- Mechanismus řízení toku dat.
- Přijímač nastavuje velikost okénka podle svých možností.
- Odesílatel může poslat více paketů bez potvrzení, dokud nedosáhne velikosti okénka.
- Zvyšuje efektivitu přenosu a zabraňuje zahlcení přijímače.

# SP-25-7
## front
Jak TCP zabraňuje zahlcení (congestion control)? Jaká veličina je k tomu využívána?
## back
- TCP nastavuje velikost tzv. congestion window (CWL).
- Odesílatel může mít otevřené jen určité množství neoznacených paketů (dané velikostí CWL).
- Po výpadku (ztrátě paketů) některé druhy TCP zvyšují CWL rychleji, jiné pomaleji.
- Viz ilustrace:

# SP-25-8
## front
Porovnej TCP a UDP z pohledu spolehlivosti, rychlosti a typických použití.
## back
- TCP:
  - Spolehlivý přenos (doručení, pořadí paketů, řízení toku, zahlcení)
  - Vyšší režie, nižší propustnost
  - Používá se např. pro web, email
- UDP:
  - Nespolehlivý přenos (bez doručení, pořadí, bez řízení toku/zahlcení)
  - Nižší režie, vyšší propustnost
  - Používaný pro hlas, video, online hry

# SP-25-10
## front
Jak NAT (Network Address Translation) využívá porty transportní vrstvy?
## back
- Překládá IP adresy více zařízení za routerem, zároveň překládá porty.
- Vytváří mapování: výstupní port <-> konkrétní IP a port uvnitř sítě.
- Při odpovědi z internetu router podle portu určí, kterému zařízení data předat.

# SP-25-11
## front
K čemu slouží systém DNS (Domain Name System)?
## back
- Slouží k překladu doménových jmen na IP adresy a naopak.
- Umožňuje používat snadno zapamatovatelná jména místo číselných IP.
- Zásadní i pro další služby (např. email).

# SP-25-12
## front
Jaké jsou hlavní vlastnosti DNS?
## back
- Hierarchický (uspořádán do stromu domén)
- Nezabezpečený (v základní verzi)
- Typicky používá port 53 a UDP
- Podporuje reverzní překlad (IP na jméno), DNSSEC (zabezpečení pomocí asymetrické kryptografie) a dynamický DNS (změny IP adresy)

# SP-25-13
## front
Jakou roli má port 53 v komunikaci DNS?
## back
- Port 53 je standardní port, na kterém běží DNS.
- Většina implementací DNS využívá UDP na tomto portu.

# SP-25-14
## front
Vysvětli hierarchii domén v systému DNS a ukaž obrázek.
## back
- DNS je hierarchický, rozdělený na domény různých úrovní:
  1. Root (kořenový server, .)
  2. TLD (Top-level domény, např. .com, .cz)
  3. Druhá úroveň (např. seznam.cz)
  4. Třetí úroveň atd. (např. mail.seznam.cz)

# SP-25-15
## front
Uveď a popiš 4 typy domén nejvyšší úrovně (TLD) v DNS.
## back
1. Generic TLD (gTLD) – 3 znaky označující typ organizace (např. gov, mil, edu, org, com, net)
2. Country Code TLD – 2 znaky označující zemi (např. cz, us, de, eu)
3. New Generic TLD – libovolný řetězec (max. 63 znaků)
4. Reverzní doména – in-addr.arpa (pro překlad IP na jméno)

# SP-25-16
## front
Jaké dva základní způsoby dotazování existují v DNS?
## back
- Iterativní dotazování:
  - Klient se ptá svého lokálního DNS serveru.
  - Ten postupně dotazuje další servery (root, TLD, atd.), sám sestavuje odpověď.
- Rekurzivní dotazování:
  - Každý DNS server dotaz předává dále (lokální → root → TLD → …)
  - První server získá konečnou odpověď a vrátí ji klientovi.

# SP-25-17
## front
Jaký význam mají následující pojmy v kontextu DNS? DNSSEC, DynDNS
## back
- DNSSEC: Zabezpečený DNS, ověřuje autentičnost odpovědí pomocí asymetrické kryptografie.
- DynDNS (dynamické DNS): Umožňuje použití doménového jména i pro zařízení s častou změnou IP adresy.

# SP-25-18
## front
Jak fungoval překlad domén před zavedením DNS?
## back
Dříve byl překlad domén prováděn pomocí centralizovaného souboru hosts.txt, ve kterém byla namapovaná jména na IP adresy ručně pro celé internetové prostředí.

# SP-25-19
## front
Jaký typ protokolu je vhodnější pro přenos hlasu nebo videa? Proč?
## back
- Pro přenos hlasu nebo videa je vhodnější UDP.
- Má nižší režii a vyšší propustnost než TCP.
- Lepší zvládání ztráty paketů (ztracený paket se nečeká, minimalizuje zpoždění).
