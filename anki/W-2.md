
# W-1-1
## front
Co je HTTP protokol a jaké jsou jeho základní vlastnosti?
## back
- HTTP je aplikační protokol pro přenos textových dat mezi klientem a serverem.
- Pracuje na principu architektury klient-server.
- Je bezstavový (stateless); "stav" se uchovává externě, např. cookies, URL parametry, session storage.
- Funguje nad TCP/IP (port 80 pro HTTP, 443 pro HTTPS).
- Umožňuje používání HTTP hlaviček pro přenos metadat.

# W-1-2
## front
Jaké jsou základní rozdíly mezi HTTP/1.1, HTTP/2 a HTTP/3?
## back
- Multiplexace:
  - HTTP/1.1: Ne
  - HTTP/2: Ano (1 TCP spojení)
  - HTTP/3: Ano (QUIC – UDP)
- Binární protokol:
  - HTTP/1.1: Ne (textový)
  - HTTP/2: Ano
  - HTTP/3: Ano
- Server push:
  - HTTP/1.1: Ne
  - HTTP/2: Ano
  - HTTP/3: Ano
- Prioritizace:
  - HTTP/1.1: Ne
  - HTTP/2: Ano
  - HTTP/3: Ano
- Transportní protokol:
  - HTTP/1.1: TCP
  - HTTP/2: TCP
  - HTTP/3: QUIC (UDP)

# W-1-3
## front
K čemu slouží HTTP hlavičky? Vyjmenuj alespoň 5 běžně používaných.
## back
HTTP hlavičky slouží k přenosu metadat mezi klientem a serverem (např. informace o požadavku/odpovědi). Příklady:
- User-Agent: informace o prohlížeči/aplikaci
- Content-Type: typ odesílaného obsahu (např. application/json)
- Accept: akceptované typy obsahu klientem
- Authorization: ověření identity uživatele (např. token)
- Cookie: odesílání cookies
- Set-Cookie: nastavení cookie klientovi
- Cache-Control: řízení mezipaměti
- Content-Length: délka obsahu v bajtech
- Location: URL pro přesměrování
- Connection: řízení spojení (keep-alive, close)

# W-1-4
## front
Jaký je rozdíl mezi URI, URL a URN? (viz obrázek)
![URI, URL, URN](img/screenshot_2025-04-25_11-53-53.png)
## back
- URI (Uniform Resource Identifier): obecný identifikátor zdroje (může být URL nebo URN)
- URL (Uniform Resource Locator): specifikuje adresu zdroje a způsob přístupu (protokol, doména, cesta apod.)
- URN (Uniform Resource Name): identifikuje zdroj jménem, ale nemusí specifikovat jeho umístění (např. ISBN)

# W-1-5
## front
Popiš strukturu HTTP požadavku na základě tohoto příkladu:
\begin{lstlisting}
POST /api/v1/users HTTP/1.1
Host: example.com
Content-Type: application/json
{
    "username": "example",
    "password" "password"
}
\end{lstlisting}
## back
Struktura HTTP požadavku:
- První řádek (request line): obsahuje metodu (POST), cestu (/api/v1/users), verzi protokolu (HTTP/1.1)
- Hlavičky (headers): např. Host, Content-Type apod.
- Prázdný řádek oddělující hlavičky od těla
- Tělo požadavku (body): data odesílaná metodou POST (např. JSON objekt s přihlašovacími údaji)

# W-1-7
## front
K čemu slouží status kódy HTTP a jaké jsou jejich hlavní kategorie?
## back
Status kódy HTTP informují klienta o výsledku požadavku. Hlavní kategorie:
- 1xx (Informational): průběh požadavku (např. 100 Continue)
- 2xx (Success): úspěšné zpracování (např. 200 OK, 201 Created)
- 3xx (Redirection): přesměrování (např. 301 Moved Permanently, 302 Found)
- 4xx (Client Error): chyba na straně klienta (např. 400 Bad Request, 401 Unauthorized, 404 Not Found)
- 5xx (Server Error): chyba na straně serveru (např. 500 Internal Server Error, 502 Bad Gateway)

# W-1-8
## front
Jaké jsou základní HTTP metody a jejich účel?
## back
- GET: získání dat ze serveru (bez těla požadavku)
- HEAD: získání pouze hlaviček odpovědi (bez těla)
- POST: odeslání (vytvoření) dat na server
- PUT: aktualizace nebo vytvoření zdroje (idempotentní)
- DELETE: odstranění zdroje
- OPTIONS: zjištění podporovaných metod (často pro CORS)

# W-1-9
## front
Co znamená, že HTTP je bezstavový protokol? Jak lze udržovat stav mezi požadavky?
## back
- HTTP je bezstavový (stateless): Každý požadavek je nezávislý, server si nepamatuje předchozí požadavky klienta.
- Stav lze udržovat externě: pomocí cookies, URL parametrů, session storage apod.

# W-1-10
## front
Jak probíhá komunikace mezi klientem a serverem přes internet? (viz obrázek)
![Komunikace klient server přes internet](img/screenshot_2025-04-25_21-05-04.png)
## back
- Klient odešle HTTP požadavek (např. přes webový prohlížeč) na server.
- Požadavek postupuje přes síťové vrstvy (např. DNS, proxy nebo reverse proxy) k origin serveru.
- Server zpracuje požadavek a pošle HTTP odpověď zpět klientovi.

# W-1-11
## front
Vysvětli pojmy DNS, proxy, reverse proxy a origin server v architektuře webové komunikace.
## back
- DNS (Domain Name System): překlad doménového jména na IP adresu serveru.
- Proxy: meziserver mezi klientem a internetem, zpracovává/proxy požadavky klientů.
- Reverse proxy: meziserver mezi internetem a jedním/mnoha servery, rozděluje provoz, poskytuje šifrování, kešování a zabezpečení.
- Origin server: původní cílový server, kde žije samotný obsah.

# W-1-12
## front
Vyjmenuj a vysvětli význam následujících hlaviček: User-Agent, Content-Type, Accept, Cookie, Authorization.
## back
- User-Agent: Identifikuje software klienta (prohlížeč, mobilní aplikace apod.).
- Content-Type: Určuje typ obsahu v těle požadavku, např. application/json.
- Accept: Udává, jaké typy obsahu klient přijímá (např. text/html, application/json).
- Cookie: Odesílá uložené cookies z klienta na server.
- Authorization: Obsahuje údaje k ověření uživatele (například Bearer token).

# W-1-13
## front
Co dělá hlavička Set-Cookie a jaký je rozdíl oproti Cookie?
## back
- Set-Cookie: Server ji posílá klientovi v odpovědi, aby nastavil, aktualizoval nebo smazal cookie v prohlížeči.
- Cookie: Klient ji posílá serveru v požadavcích; obsahuje uložené cookies.

# W-1-14
## front
Jaké bezpečnostní riziko má HTTP a jak ho řeší HTTPS?
## back
- HTTP neposkytuje šifrování; data lze snadno odposlouchávat třetími stranami.
- HTTPS (HTTP přes TLS/SSL) zajišťuje:
  - Šifrování dat mezi klientem a serverem.
  - Ověření identity serveru pomocí certifikátů.
  - Integritu dat během přenosu.

# W-1-15
## front
Jaké typy informací lze najít v hlavičkách Cache-Control, Content-Length, Location, Connection?
## back
- Cache-Control: řízení mezipaměti (např. no-cache, max-age)
- Content-Length: délka těla zprávy v bajtech
- Location: adresa pro přesměrování (status kód 3xx)
- Connection: řízení spojení (např. keep-alive, close)

# W-1-16
## front
Vyjmenuj možnosti vyjádření jazykových a kódovacích preferencí v HTTP hlavičkách.
## back
- Accept-Encoding: typy kódování, které klient akceptuje (např. gzip, deflate)
- Accept-Language: jazykové preference klienta (např. en-US, cs-CZ)

# W-1-17
## front
Vysvětli výhody HTTPS nad HTTP.
## back
- Šifrování: zabezpečení komunikace před odposlechem třetími stranami.
- Ověření: zaručení identity serveru pomocí certifikátů.
- Integrita: ochrana před manipulací dat během přenosu.

# W-1-18
## front
Které HTTP metody jsou idempotentní a co to znamená?
## back
- Idempotentní: opakované volání stejné operace má stejný výsledek jako jednorázové.
- Idempotentní HTTP metody: GET, PUT, DELETE, HEAD, OPTIONS.

# W-1-19
## front
Co znamená v HTTP hlavičce Origin a Referer?
## back
- Origin: původní doména, ze které byl požadavek odeslán (používá se pro CORS).
- Referer: URL stránky, ze které byl požadavek odeslán.

# W-1-20
## front
Vyjmenuj a přiřaď statusové kódy k jednotlivým kategoriím:
a) 200 OK
b) 302 Found
c) 404 Not Found
d) 500 Internal Server Error
e) 100 Continue
## back
- 200 OK: 2xx (Success)
- 302 Found: 3xx (Redirection)
- 404 Not Found: 4xx (Client Error)
- 500 Internal Server Error: 5xx (Server Error)
- 100 Continue: 1xx (Informational)
