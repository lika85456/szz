
# W-1-1
## front
Jaké jsou hlavní části HTTP požadavku (request)?
## back
- Request line (metoda, cesta, HTTP verze)
- Headers (hlavičky)
- Tělo požadavku (body) – pouze u některých metod (např. POST, PUT)

# W-1-2
## front
Jaké části tvoří HTTP odpověď (response)?
## back
- Status line (HTTP verze, stavový kód, zpráva)
- Headers (hlavičky)
- Tělo odpovědi (body)

# W-1-3
## front
Vyjmenuj a popiš základní metody HTTP požadavku.
## back
- GET: Získání dat ze serveru.
- POST: Zaslání dat na server (např. formulář, vytvoření záznamu).
- PUT: Aktualizace existujícího záznamu.
- DELETE: Smazání dat.
- HEAD: Stejné jako GET, ale bez těla odpovědi.
- PATCH: Částečná aktualizace zdroje.

# W-1-4
## front
Co znamená, že HTTP je bezstavový protokol?
## back
- Každý HTTP požadavek je nezávislý.
- Server si nepamatuje žádné informace o předchozích požadavcích od stejného klienta.
- Stav je nutné uchovávat jinými mechanismy (např. cookies, session).

# W-1-5
## front
Vyjmenuj a stručně popiš způsoby udržení stavu ve webové aplikaci.
## back
- URL: Parametry v URL (query string, path parametry); stav lze snadno sdílet, není vhodné pro citlivá data.
- Cookies: Úložiště na straně klienta, omezená velikost, klíč-hodnota, možnost nastavení platnosti.
- Session: Úložiště na serveru (databáze), klient uchovává pouze session id (obvykle v cookie).
- Local Storage: Úložiště na straně klienta pro větší množství dat, není automaticky odesíláno se žádostí.
- JavaScript proměnné: Uchování stavu v běžící JS aplikaci (po reloadu se ztrácí).

# W-1-6
## front
Jaké jsou výhody a nevýhody ukládání stavu v URL?
## back
Výhody:
- Snadné sdílení odkazu včetně stavu (bookmarks, sdílení URL).
Nevýhody:
- Nevhodné pro citlivá data (snadno čitelná, ukládání do historie prohlížeče).
- Omezená délka URL.

# W-1-7
## front
K čemu slouží cookies ve webové aplikaci? Jaká jsou jejich omezení?
## back
- Slouží k ukládání dat na straně klienta, např. pro udržení přihlášení nebo sledování uživatele.
- Omezená velikost (cca 4 KB na cookie).
- Klíč-hodnota.
- Možnost nastavení platnosti, domény, cesty, příznaku HttpOnly a Secure.

# W-1-8
## front
Popiš, jak funguje mechanismus session udržování stavu.
## back
- Stav (např. přihlášení uživatele) je uložen na serveru (v paměti nebo databázi).
- Klient obdrží jedinečné session id (typicky v cookie), které posílá s každým požadavkem.
- Server podle session id najde odpovídající uložená data.

# W-1-9
## front
K čemu slouží Local Storage ve webových aplikacích?
## back
- Úložiště na straně klienta, umožňuje ukládání větších objemů dat (obvykle až několik MB pro doménu).
- Data nejsou automaticky odesílána serveru.
- Přístup z JavaScriptu (window.localStorage).

# W-1-10
## front
Jaký je rozdíl mezi ukládáním stavu do session a do cookies?
## back
- Cookies: Data jsou uložena na straně klienta, posílají se s každým požadavkem na server.
- Session: Identifikátor session je uložen v cookie, ale samotná data jsou uložena na serveru.

# W-1-11
## front
Doplň: Pro dočasné uchování stavu během běhu stránky lze v JavaScriptu použít ______.
## back
- JavaScript proměnné (například v rámci globální proměnné, closure, nebo ve frameworku)
- Platí pouze po dobu načtení stránky (po reloadu se ztratí).

# W-1-12
## front
Vysvětli výhody a nevýhody používání session k ukládání stavu.
## back
Výhody:
- Citlivá data nejsou u klienta.
- Větší bezpečnost.
Nevýhody:
- Vyšší nároky na server (musí uchovávat session pro více klientů).
- Vypršení session znamená ztrátu stavu.

# W-1-13
## front
Proč není vhodné ukládat citlivá data do URL?
## back
- URL jsou snadno dostupná (zobrazují se v adresním řádku, historii prohlížeče).
- URL může být sdíleno nechtěně či automaticky (např. referer v požadavcích na jiné domény).

# W-1-14
## front
Jaké stavové informace lze typicky uložit do cookies?
## back
- Session id
- Uživatelské předvolby (např. jazyk rozhraní)
- Auth tokeny (např. JWT)
- Tracking (analytics information)

# W-1-15
## front
Jak se přenáší session id mezi klientem a serverem?
## back
- Nejčastěji v cookie, kterou server nastaví při přihlášení uživatele.
- Klient posílá cookie v každém dalším požadavku na server.

# W-1-16
## front
Jaký vztah má local storage a cookies z hlediska životnosti dat?
## back
- Data v local storage zůstávají, dokud je uživatel nebo skript neodstraní.
- Cookies mohou mít omezenou životnost (expiration date, session cookies).

# W-1-17
## front
Jakou roli hrají HTTP hlavičky v požadavku i odpovědi?
## back
- Přenáší dodatečné informace o požadavku/odpovědi (např. typ obsahu, délka, cookies, autentizace, cacheování apod.).

# W-1-18
## front
Vyjmenuj rozdíly mezi local storage, cookies a session z hlediska dostupnosti dat.
## back
- Local storage: dostupné pouze na straně klienta v rámci domény, přístupné z JavaScriptu.
- Cookies: k datům má přístup klient (JavaScript, pokud není HttpOnly) i server (automaticky odesíláno).
- Session: data uložena pouze na serveru, klient zná pouze session id.

# W-1-19
## front
Co znamená, že HTTP je protokol typu request-response?
## back
- Klient vždy pošle požadavek (request), server odpoví odpovědí (response).
- Server neposílá data bez předchozího požadavku klienta.

# W-1-20
## front
Vysvětli použití query string v URL pro udržení stavu.
## back
- Query string obsahuje parametry za otazníkem v URL ($?klic=hodnota$).
- Lze použít pro přenos filtru, stránkování, mezistavu a podobných informací.
- Není vhodné pro citlivá data.
