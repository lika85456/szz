
# W-1-1
## front
Co je to webový server a jakou hlavní úlohu plní v síťové komunikaci?
## back
- Webový server je software (a často i hardware), který přijímá HTTP(S) požadavky od klientů (např. webových prohlížečů).
- Zpracovává je a vrací odpovědi, obvykle ve formě HTML dokumentů, souborů nebo dynamicky generovaného výstupu.
- Hlavní úlohou je poskytování webového obsahu klientům na základě protokolů jako HTTP/1.1, HTTP/2 a HTTP/3.

# W-1-2
## front
Popište obecný průběh zpracování HTTP požadavku webovým serverem.
## back
1. Klient odešle HTTP požadavek na IP adresu serveru (obvykle port 80 pro HTTP nebo 443 pro HTTPS).
2. Server naslouchá na daném portu a přijme požadavek.
3. Server analyzuje požadavek: metodu (např. GET, POST), URI, hlavičky atd.
4. Na základě URI identifikuje požadovaný zdroj.
5. Server rozhodne, zda:
   - Vrátí statický soubor;
   - Předá požadavek dynamickému skriptu.
6. Server vygeneruje HTTP odpověď a odešle ji klientovi.

# W-1-3
## front
Vyjmenujte hlavní typy obsahu, které může webový server poskytovat, a stručně je charakterizujte.
## back
- Statický obsah:
  - Soubory uložené na disku (např. .html, .css, .js, obrázky, PDF).
  - Server pouze přečte a odešle klientovi.
  - Výhoda: rychlost, efektivita.
  - Nevýhoda: nelze přizpůsobit uživateli.
- Dynamický obsah:
  - Generován při požadavku (např. PHP, Python, Node.js).
  - Může záviset na vstupu uživatele, databázi apod.
  - Výhoda: personalizace, interaktivita.
  - Nevýhoda: vyšší nároky na výkon.

# W-1-4
## front
Jaký je rozdíl mezi statickým a dynamickým obsahem na webovém serveru?
## back
- Statický obsah:
  - Nemění se, uložený jako soubor na serveru.
  - Server pouze soubor přečte a pošle klientovi.
- Dynamický obsah:
  - Generuje se za běhu na základě požadavku, často skriptem.
  - Výstup může záviset na datech z databáze nebo na uživatelském vstupu.
  - Realizace například pomocí CGI, FastCGI, mod_php, mod_python atd.

# W-1-5
## front
Jaké jsou výhody a nevýhody poskytování statického obsahu webovým serverem?
## back
- Výhody:
  - Velmi rychlé a efektivní obsloužení požadavků.
  - Nízké nároky na výkon serveru.
- Nevýhody:
  - Nelze snadno přizpůsobit obsah uživateli.
  - Není možné generovat obsah podle aktuální situace nebo uživatelského vstupu.

# W-1-6
## front
Jaké způsoby paralelního zpracování požadavků používají moderní webové servery?
## back
- Víceprocesové zpracování – každý požadavek obsluhuje samostatný proces.
- Vláknové zpracování – každý požadavek obsluhuje samostatné vlákno v rámci procesu.
- Asynchronní (event-driven) zpracování – jeden proces obsluhuje více požadavků pomocí událostí (např. Nginx).

# W-1-7
## front
Co je to MPM (Multi-Processing Module) v Apache HTTP Serveru a jaké typy nabízí?
## back
- MPM (Multi-Processing Module) v Apache HTTPD určuje způsob paralelního zpracování požadavků.
- Typy MPM:
  - prefork: každý požadavek zpracovává samostatný proces; nevhodné pro thread-unsafe moduly, vyšší paměťová náročnost.
  - worker: každý proces má více vláken; efektivnější, vyžaduje thread-safe moduly.
  - event: rozšíření worker, neblokující obsluha KeepAlive, moderní a výkonné řešení pro většinu produkčních nasazení.

# W-1-8
## front
Který MPM modul Apache HTTPD je doporučován pro moderní produkční nasazení a proč?
## back
- Doporučovaný je MPM "event":
  - Poskytuje moderní, výkonné a efektivní paralelní zpracování.
  - Umožňuje neblokující obsluhu KeepAlive požadavků.
  - Vhodný pro většinu produkčních nasazení.

# W-1-9
## front
Vysvětlete víceprocesový a vláknový model paralelizace v kontextu webových serverů.
## back
- Víceprocesový model:
  - Každý požadavek je obsluhován samostatným procesem.
  - Výhoda: lepší izolace, vyšší stabilita.
  - Nevýhoda: vyšší paměťová náročnost, horší škálovatelnost.
- Vláknový model:
  - Každý požadavek je obsluhován samostatným vláknem v rámci jednoho procesu.
  - Výhoda: lepší sdílení zdrojů, nižší paměťová zátěž, vyšší efektivita.
  - Nevýhoda: nutnost thread-safe programů.

# W-1-10
## front
Jak Apache HTTPD obsluhuje statický obsah? Vyjmenujte příslušné moduly a jejich účel.
## back
- Obsluha statického obsahu v Apache HTTPD je realizována pomocí modulů:
  - mod_alias: přepis a mapování URL na soubory.
  - mod_autoindex: generování indexu (seznamu souborů) ve složce.
  - mod_mime: určení typu souboru (MIME type) podle přípony.
- Typická konfigurace:
  - DocumentRoot určuje kořenový adresář.
  - Při požadavku na kořenový adresář vrací server soubor index.html.

# W-1-11
## front
Jak Apache HTTPD obsluhuje dynamický obsah? Uveďte příslušné moduly a popis jejich fungování.
## back
- Moduly pro obsluhu dynamického obsahu:
  - mod_php: přímo interpretuje PHP skripty.
  - mod_cgi, mod_fcgid: spouští externí programy jako CGI (např. Python, Perl).
  - mod_proxy_fcgi: proxy pro FastCGI procesy (např. PHP-FPM).
- Například požadavek na PHP skript je přesměrován na FastCGI backend, kde je skript zpracován a výsledek vrácen klientovi.

# W-1-12
## front
K čemu slouží v Apache HTTPD modul mod_proxy_fcgi a jaký je typický příklad jeho použití?
## back
- mod_proxy_fcgi slouží jako proxy mezi Apache HTTPD a FastCGI backendem (např. PHP-FPM).
- Umožňuje Apache předávat požadavky na dynamické skripty backendům, které je rychleji a efektivněji zpracují.
- Typický příklad:
  - Konfigurace pro předání PHP skriptů FastCGI backendu:
    ```
    <FilesMatch \.php$>
        SetHandler "proxy:unix:/run/php/php8.1-fpm.sock|fcgi://localhost"
    </FilesMatch>
    ```

# W-1-13

Vyjmenujte (alespoň) tři základní doporučení pro efektivní nasazení webových serverů v praxi.
## back

# W-1-15
## front
Popište stručně, jak lze konfigurovat obsluhu statického obsahu v Apache HTTPD.
## back
- Statický obsah je umístěn v adresáři definovaném pomocí direktivy DocumentRoot.
- Přístupová práva a chování nastavují sekce Directory.
- Modul mod_alias umožňuje přepis cesty, mod_autoindex generuje indexy a mod_mime nastavuje typ souboru.
- Například:
  ```
  DocumentRoot "/var/www/html"
  <Directory "/var/www/html">
      Options Indexes FollowSymLinks
      AllowOverride None
      Require all granted
  </Directory>
  ```

# W-1-16
## front
Jaký je rozdíl mezi CGI a FastCGI při zpracování dynamických požadavků?
## back
- CGI (Common Gateway Interface):
  - Pro každý požadavek se spouští nový proces, což způsobuje velkou režii.
- FastCGI:
  - Procesy běží trvale na pozadí, požadavky jsou jim předávány bez nutnosti stále vytvářet nové procesy.
  - Výrazně rychlejší, vhodné pro větší provoz.

# W-1-17
## front
Vyjmenujte moderní protokoly HTTP a jejich význam pro webové servery.
## back
- HTTP/1.1: základní rozšířená a široce používaná verze.
- HTTP/2: podpora multiplexingu, zvyšuje efektivitu přenosu dat.
- HTTP/3: využívá QUIC, další zrychlení a bezpečnost přenosu.

# W-1-18
## front
Co zajišťuje v Apache HTTPD "mod_mime"?
## back
- Modul mod_mime určuje MIME typy souborů na základě jejich přípon.
- Umožňuje serveru správně informovat klienta o typu přenášeného souboru (např. text/html, image/png).

# W-1-19
## front
Proč je vhodné oddělit obsluhu dynamického obsahu do specializovaných backendů (např. PHP-FPM, uWSGI)?
## back
- Oddělení umožní lepší škálovatelnost a vyšší efektivitu.
- Specializované backendy jsou optimalizované na daný jazyk/technologii.
- Lze nezávisle ladit výkon a bezpečnostní pravidla pro každý typ obsahu.

# W-1-20
## front
Jakou roli hraje v Apache HTTPD konfigurace "DocumentRoot"?
## back
- Definuje kořenový adresář pro webové stránky/služby, odkud server poskytuje statické soubory.
- Požadavky na cestu "/" jsou směrovány na obsah tohoto adresáře.
