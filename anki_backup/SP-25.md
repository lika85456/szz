
# SP-25-1
## front
Jakou úlohu plní transportní vrstva v modelu síťových vrstev? Vyjmenujte hlavní funkce transportní vrstvy.
## back
- Zajišťuje doručení dat konkrétním aplikacím (identifikace pomocí portů vedle IP adresy).
- Řeší spolehlivost dodání dat.
- Poskytuje řízení toku a spolehlivosti (např. mechanismy: stop and wait, stop and go, sliding window).

# SP-25-2
## front
Popište stručně rozdíly mezi mechanismy spolehlivého doručení dat: stop and wait, stop and go a sliding window.
## back
- Stop and wait:
  - Odesílatel pošle jeden segment a čeká na potvrzení (ACK).
  - Efektivní při malém zpoždění, nevhodné pro dlouhé linky nebo velká data.
- Stop and go:
  - Přijímač posílá "stop" a "go" signály odesílateli; nemusí zajistit správné doručení.
- Sliding window:
  - Odesílatel může poslat více segmentů v okně velikosti $N$ bez čekání na jednotlivé ACK.
  - Zvýšení propustnosti a efektivity, řízení toku a pořadí doručení.

# SP-25-3
## front
K čemu slouží port v transportní vrstvě? Vyplňte:
Porty umožňují _________.
## back
Porty umožňují jednoznačnou identifikaci konkrétní aplikace (procesu) na cílovém zařízení, kam mají být data doručena v rámci IP adresy.

# SP-25-4
## front
Co garantuje protokol TCP na rozdíl od UDP? Vyjmenujte vlastnosti TCP.
## back
- TCP (Transmission Control Protocol) garantuje:
  - Spolehlivé doručení dat (opakování při ztrátě).
  - Zachování pořadí paketů.
  - Řízení toku a zahlcení.
  - Je duplexní (obě strany mohou posílat i přijímat souběžně).
  - Spojení-oriented (musí být navázáno a ukončeno spojení).

# SP-25-5
## front
Doplňte schéma: ![Obrázek TCP třífázového handshake](img/SP-25_0.jpg)
Jaký je postup navázání spojení v TCP (three-way handshake)?
## back
- Postup navázání spojení v TCP:
  1. Klient vyšle segment s příznakem SYN.
  2. Server odpoví segmentem SYN-ACK.
  3. Klient pošle potvrzení ACK.
- Spojení je navázáno a data mohou proudit oběma směry.

# SP-25-6
## front
![Obrázek struktury TCP paketu](img/SP-25_1.jpg)
Popište základní pole v hlavičce TCP segmentu.
## back
- Zdrojový port ($Source\ Port$)
- Cílový port ($Destination\ Port$)
- Pořadové číslo ($Sequence\ Number$)
- Potvrzovací číslo ($Acknowledgement\ Number$)
- Data offset, rezervováno, příznaky (flags, např. SYN, ACK, FIN)
- Okno (Window size)
- Kontrolní součet ($Checksum$)
- Urgent pointer (pro urgentní data)
- Volitelné pole (Options)
- Data (Payload)

# SP-25-7
## front
Vysvětlete princip klouzavého okénka (sliding window) v TCP.
## back
- Sliding window mechanismus:
  - Umožňuje odesílat více segmentů bez čekání na potvrzení každého z nich.
  - Přijímač určuje velikost okna podle své schopnosti zpracovat data.
  - Zajišťuje efektivnější využití sítě a řízení toku.

# SP-25-8
## front
Jak řeší protokol TCP problém zahlcení (congestion control)?
## back
- TCP používá mechanismus řízení zahlcení (congestion control):
  - Pro řízení využívá veličinu CWL (congestion window length).
  - Odesílatel postupně zvyšuje velikost okna (slow start, congestion avoidance).
  - Po zjištění přetížení sítě (např. ztráta paketů) snižuje rychlost odesílání.
  - Různé varianty TCP mají různé strategie obnovy rychlosti po zahlcení.

# SP-25-9
## front
![Obrázek s mechanismem TCP zahlcení](img/SP-25_2.jpg)

- Po zahlcení postupný nárůst kapacity podle varianty TCP.

# SP-25-10
## front
Vyjmenujte výhody a nevýhody protokolu UDP ve srovnání s TCP.
## back
Výhody UDP:
- Nižší režie (jednodušší hlavička).
- Vyšší propustnost.
- Vhodný pro aplikace citlivé na zpoždění (hlas, video).

Nevýhody UDP:
- Nezajišťuje spolehlivost ani pořadí doručení.
- Bez řízení toku a zahlcení.

# SP-25-12
## front
Jak funguje síťový překlad adres (NAT) na úrovni transportní vrstvy? Proč díky portům může NAT fungovat?
## back
- NAT (Network Address Translation) využívá porty k rozlišení více spojení za jednou veřejnou IP adresou.
- Na routeru je mapování mezi vnitřní IP+port a vnější IP+port.
- Směrem ven je IP adresa a případně port nahrazen adresou/routeru.
- Při odpovědi router podle portu pozná, na který vnitřní počítač a port má data předat.
- Porty umožňují více zařízení sdílet jednu veřejnou IP adresu.

# SP-25-13
## front
Proč je potřebný systém doménových jmen (DNS)? Vyjmenujte jeho hlavní funkce.
## back
- IP adresy jsou pro lidi obtížně zapamatovatelné.
- DNS umožňuje překlad doménových jmen na IP adresy (a zpět).
- Základní služby:
  - Překlad domén na IP adresy.
  - Opačný překlad (reverzní DNS).
  - Důležitý i pro jiné služby (např. email).

# SP-25-14
## front
Jaký charakter má DNS z pohledu architektury? Jaké porty a protokoly využívá?
## back
- DNS je hierarchický systém doménových serverů.
- Tradičně je nezabezpečený (existují rozšíření jako DNSSEC).
- Standardně používá port 53.
- Obvykle využívá UDP, v některých situacích i TCP.

# SP-25-15
## front
![Obrázek hierarchie DNS](img/SP-25_5.jpg)
Popište hierarchii doménových jmen v DNS.
## back
- Hierarchická struktura domén:
  - Root (kořen) – značený tečkou.
  - Top Level Domain (TLD) – např. .cz, .com.
  - Second Level Domain – např. seznam.cz.
  - Třetí a další úrovně – např. mail.seznam.cz.
- Každý stupeň spravují jiné subjekty (delegace odpovědnosti).

# SP-25-16
## front
Jaké existují typy TLD (Top Level Domains) v DNS? Vyjmenujte příklady.
## back
- Generic TLD (gTLD): tříznaková doménová jména podle funkce (např. .com, .org, .net, .edu, .gov, .mil)
- Country Code TLD (ccTLD): dvouznakové domény podle států (např. .cz, .us, .de, .eu)
- New Generic TLD: libovolný řetězec (maximálně 63 znaků)
- Reverzní doména: in-addr.arpa (používá se např. pro zpětný překlad IP na doménu)

# SP-25-17
## front
Vysvětlete rozdíl mezi iterativním a rekurzivním způsobem dotazování v DNS.
## back
- Iterativní dotazování:
  - Klient (místní DNS server) se ptá postupně (root, TLD, SLD...) a každý server odpoví buď konečným záznamem, nebo odkazem na další server.
- Rekurzivní dotazování:
  - Dotaz je přeposlán "dovnitř" systému a odpověď se klientovi vrací hotová.
  - Lokální DNS server provede celý postup i dotazování dalších serverů za klienta.

# SP-25-18
## front
Co je to DNSSEC a jaký problém řeší?
## back
- DNSSEC (DNS Security Extensions) rozšiřuje DNS o bezpečnost.
- Přidává ověření pravosti dat pomocí digitálních podpisů (asymetrická kryptografie).
- Chrání před podvržením/pozměněním záznamů (DNS spoofing, cache poisoning).

# SP-25-19
## front
Kdy se používá dynamické DNS (DynDNS)?
## back
- Používá se, pokud zařízení často mění svou IP adresu (např. domácí připojení s dynamickou adresou od poskytovatele).
- Umožňuje aktualizovat odpovídající záznam(y) v DNS automaticky podle aktuální IP adresy.
- Například pro vzdálený přístup ke službám v domácí síti.
